# 内置模型额度 · 服务条款与可接受使用政策

> 生效日期：2026-09-19（上海时间）
> 适用对象：使用 HunterCode（猎鹿人开源版）**内置模型额度**的自部署用户
> 版本：v1（English version: [terms-of-service.md](./terms-of-service.md)）
> 本文档随开源仓库一起版本化 —— 改了哪一句，`git log` 上看得到。

---

## 零、一句话

内置模型额度是我们**免费提供给 HunterCode 自部署用户的起步路径**，
让你不用自己去找大模型 key 就能开始用。它不是一个通用 LLM API，
不保证永远存在，也不保证额度一直是今天这个数。
**我们只记录 token 数与模型名，不记录任何对话内容。**

不接受这几条的话，走自带 key 或本地模型那条路 —— 它们始终是一等公民，
功能上不比内置额度少任何一项。

---

## 一、这项服务是什么

「内置模型额度」指：你用一把 HunterCode 平台 key（`hunt_tools_` 开头）
访问我们的网关 `https://hunter.agentpit.io/api/saas/llm/*`，
由我们代为调用上游大模型并承担费用。网关只暴露两个模型别名：

| 别名 | 用途 |
|---|---|
| `hunter-chat` | 默认对话与工具调用 |
| `hunter-deep` | 深度分析与长任务 |

**提供方**：HunterCode / agentpit（下称「我们」）。

---

## 二、谁可以用

仅限**已申请 HunterCode 平台 key 的自部署用户**，用于：

- 在自己部署的 HunterCode 实例里做投研、学习、开发与测试
- 评估 HunterCode 是否适合自己，再决定要不要换成自带 key 或商业版

这**不是**一项面向公众的生成式 AI 服务，也不是可以对外转售的 API 产品。
我们不为此做面向大陆公众的宣传；相关合规要求在取得专业意见前，
本服务维持「仅对主动申请 key 的自部署用户开放」的范围。

## 三、可接受使用政策（AUP）

### 3.1 允许

- 在你自己的 HunterCode 实例里正常对话、调用工具、跑深度分析
- 为了评估或开发而做的合理测试

### 3.2 明确禁止

1. **转售、出租、分发**额度或 key，无论收费与否。
2. **把网关当通用 API 用** —— 接到 HunterCode 以外的应用、机器人、
   聚合站、代理服务、二次分发的中转站上。
3. **脚本化刷量**：为了耗尽额度、压测、囤积 token 而发起的批量请求。
   正常使用有每分钟请求数与并发上限，绕过它们（多 key 轮换、分布式发包等）
   属于本条禁止范围。
4. **共享一把 key 给多人/多实例**长期使用。额度是按 key 发的，不是按人头发的。
5. 用它生成或传播**违法内容**，或用于攻击、欺诈、垃圾信息、规避他人安全措施。
6. 试图探测、绕过或破坏网关与上游的安全机制、额度机制、模型白名单。

### 3.3 上游的规则同样适用

网关背后是第三方大模型服务。它们各自的使用政策（内容限制、禁止用途等）
对你同样有效。我们没有能力、也不会替你豁免上游的规则。

## 四、额度

- **默认每把 key 每天 1000 万 token**（输入 + 含 thinking 的输出），
  北京时间 0 点重置。
- 还有**每分钟请求数上限与并发上限**，以及单请求的输入/输出长度上限。
- **额度、限速、模型映射都可能被调整**，恕不单独通知；
  调整会体现在本文档与网关返回的说明里。试点期结束后我们会按真实用量重新定档。
- 额度用完**不是断服**：网关会返回一段中文说明，告诉你几点重置、
  以及如何在设置里改用自己的 key。你的工具、数据供给、SKILL **不受影响**。
- 我们还设有**全平台的每日总量熔断**。触发时新请求会被暂时拒绝并提示改用自带 key。
  这是为了防止成本失控，不是针对某一个用户。

## 五、数据与隐私

### 5.1 我们记录什么

网关**只**落库这些字段：

```
key_id · 时间 · 模型别名 · 上游真实模型 · 输入 token 数 · 输出 token 数
· 是否为估算值 · 是否流式 · 是否中途断开 · 耗时毫秒 · 状态码 · 错误码
```

### 5.2 我们不记录什么

**没有 prompt、没有回复、没有工具参数、没有股票代码，一个字都没有。**

这条约束写在网关的代码注释与建表 SQL 里（`saas_llm_usage`），
作为一条对内的硬规矩：凡是名字里带 prompt / message / content / text /
response 的列一律不许加。网关代码在我们的私有仓库里，
但它的行为在开源仓的测试报告里有逐条实测记录（包括「全表转文本搜关键词 0 命中、
非 ASCII 字符 0 个」这样的验证）。

### 5.3 但请如实理解一件事

**你的问题文本会经过我们的服务器转发给上游模型**（否则无法代你调用）。
我们不留存它，但它确实经过了。上游模型服务商如何处理，取决于他们自己的政策。

如果你连「经过」都不接受，请走自带 key 或本地模型（Ollama / vLLM）那条路。
**这正是我们把内置额度设计成可选起步路径、而不是默认唯一路径的原因。**

### 5.4 其余数据仍在你自己机器上

会话正文在你的 opencode 卷里，自选股、持仓、研究记录在你自己的 Postgres 里。
内置额度**不改变**这一部分。改变的只有推理这一步发生在哪。

## 六、滥用的处置

我们按 key 记录调用次数与 token 数（不记内容），因此可以在不看任何对话的前提下
发现异常用量。发现违反第三节时，按严重程度采取：

1. **调低这把 key 的额度**（最常用、最温和，你仍能看到中文提示并切自带 key）
2. **停用这把 key** —— 注意：停用是整把 key 失效，
   工具、数据供给、Kronos 等能力会一并停掉
3. 情节严重或反复的，不再为该账号签发新 key

误伤了请联系我们（见第九节）。

## 七、服务水平（说实话的版本）

- **没有 SLA。** 这是一项免费的附带服务，不承诺可用性、延迟或不中断。
- 我们**确实**在做可用性监控（每 10 分钟探一次，连续失败会告警），
  但那是为了我们自己能及时知道，不构成对你的承诺。
- 服务**可能变更、降级、暂停或下线**。我们会尽量提前在开源仓的公告区说明，
  但紧急情况下可能先停后说。
- 网关整体停用时，你会收到一段明确的中文说明，而不是一个转圈或一句英文报错。
- **你的 HunterCode 实例不会因此不能用**：换成自带 key 是设置里的几步操作，
  已有会话、SKILL 与数据一个都不会丢。
