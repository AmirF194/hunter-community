# 03 · 镜像拉取耗时(实测)

> 只记实测值。没有测试机的网络环境写「未测」并说明原因,不估算。
> 口径:目标机器上先不存在该镜像的任何层,`docker pull` 从开始到结束的墙钟时间。
> 测量时间:2026-09-17 02:20–02:30(上海时间)。**单次采样**,公网带宽会波动,不是基准测试。

## 测量点

| 主机 | 位置 | 角色 |
|---|---|---|
| agentpit(34.133.47.117) | Google Cloud **us-central1-a** · 美国中部 | 构建机 |
| fin-r1(35.198.212.241) | Google Cloud **asia-southeast1-c** · 新加坡 | 演示站 |
| 中国大陆 | — | **未测** · 没有可用的测试机 |

## 结果

| 镜像 | 压缩大小(实际下载量) | agentpit · 美国中部 | fin-r1 · 新加坡 | 国内 |
|---|---|---|---|---|
| 旧 `hunter-opencode:dev`(7.56 GB) | 1 704 397 469 B ≈ **1.70 GB** | **123 秒**(5 层全新拉,0 层复用) | **未测** | 未测 |
| 新 `hunter-opencode:1.18.12-slim.1`(618 MB) | 152 923 316 B ≈ **153 MB** | **6 秒** | **9 秒** | 未测 |

- **旧镜像在 fin-r1 上为什么没测**:机器上本来就有这份镜像,要冷测就得先删掉它;而红线规定新版本验证通过前不得删除旧镜像(回滚要用)。宁可少一个数,不冒回滚失效的风险。
- **国内为什么没测**:手上没有国内网络的测试机。GHCR 在国内的可达性和速度差异很大,凭经验编一个数没有意义。需要国内数据的话,欢迎在 Discussions 里贴你的 `time docker pull` 结果。

## 一个顺手踩到的坑:`denied`

fin-r1 第一次拉新标签时报:

```
Error response from daemon: error from registry: denied
```

镜像是**公开**的、匿名可拉,报 denied 是因为机器上留着一份**过期的 GHCR 登录**(`~/.docker/config.json` 里有 `ghcr.io` 条目),docker 会优先带上这份凭据,而过期凭据被拒绝之后它**不会退回匿名**。

```bash
docker logout ghcr.io      # 之后匿名拉,9 秒完成
```

这条已经写进 `docs/01-getting-started.md` 的排错表。之所以值得单独写:报错是 `denied`,看上去像「镜像是私有的、我没权限」,实际原因正相反 —— 是多带了一份不该带的凭据。

## 对部署体验的影响

首次 `docker compose up -d` 的耗时构成变了:

| | 瘦身前 | 瘦身后 |
|---|---|---|
| 拉对话引擎镜像 | 大头(1.70 GB) | 已经不是大头(153 MB) |
| 本地构建 `api` + `web` | 几分钟 | 不变,现在是**主要耗时** |

也就是说,README 里「首次约 10–15 分钟」这句话的瓶颈从「下载」挪到了「本地构建前端」。
